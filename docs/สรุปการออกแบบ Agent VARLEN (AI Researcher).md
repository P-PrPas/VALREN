# สรุปการออกแบบ Agent VARLEN (AI Researcher)

Oct 26, 2026 · @P

## 1. บทบาทและขอบเขต

VARLEN เป็น Hermes agent เฉพาะทางที่ทำหน้าที่เป็น senior AI researcher ส่วนตัว: ตามเทรนด์ อ่าน paper และสอนคุณ แล้วเก็บความรู้ไว้ใน Notion second brain

ชื่อ VARLEN ย่อมาจาก Verification · Analysis · Research · Learning · Exploration Network

ในเอกสารนี้ **ตกลงแล้ว** คือสิ่งที่คุณยืนยันแล้ว ส่วน **ข้อเสนอ** คือสิ่งที่ผมเสนอและรอคุณยืนยัน

- **ตกลงแล้ว** เป็น agent แยกอีกตัวใน homelab ไม่ใช่งานย่อยของ Malren: Malren ยังเป็น personal assistant ส่วน Trevan ดูพอร์ตลงทุน
- **ตกลงแล้ว** งานหลักมี 4 อย่าง: แนะนำ GitHub repo ยอดนิยมใหม่ที่ยังไม่เคยแนะนำ, open-source model ใหม่ (ทั้ง LLM และ CV), frontier LLM ใหม่ และ paper ที่น่าสนใจทั้งใหม่และเก่า
- **ตกลงแล้ว** ความรู้ต้องไปอยู่ใน Notion second brain เพื่อให้คุณเปิดอ่านได้
- **ข้อเสนอ** บทบาทครู: เมื่อคุณสั่ง มันสอนเป็นขั้น เริ่มจากอธิบายแบบเข้าใจง่ายก่อน แล้วลงรายละเอียดเทคนิค นิยามศัพท์ทุกคำ และใช้ภาษาไทยปนศัพท์อังกฤษที่คุณใช้จริง
- **ข้อเสนอ** ขอบเขตสิทธิ์: อ่านเว็บสาธารณะและเขียนลง Research Library เท่านั้น ไม่แตะ Gmail, Calendar, GitHub ส่วนตัว หรือ secrets ของ agent ตัวอื่น
- **ข้อเสนอ** สิ่งที่ไม่ทำ: ไม่ตัดสินใจแทนคุณว่าโปรเจกต์ควรใช้เทคโนโลยีอะไร (ให้ข้อมูลและความเห็นเท่านั้น) และไม่ติดตั้งหรือรันโค้ดจาก repo ที่แนะนำ

## 2. ทำไมต้องแยกจาก Malren

แยกเป็น agent ตัวใหม่ เพราะ VARLEN ต้องอ่านเนื้อหาจากเว็บที่เราควบคุมไม่ได้ ซึ่งไม่ควรอยู่ในตัวเดียวกับ agent ที่ถือสิทธิ์เข้า Gmail, GitHub, Notion และ Calendar ของคุณ

เหตุผลเรียงตามน้ำหนัก (ทั้งหมดเป็นข้อเสนอ):

1. **ความปลอดภัย.** หน้าเว็บ, README และ paper อาจมีข้อความแอบสั่งให้ agent ทำสิ่งที่ไม่ควรทำ เรียกว่า prompt injection ถ้า VARLEN ถูกหลอก มันพังได้เท่าที่สิทธิ์มี และหลัก least privilege (ให้สิทธิ์เท่าที่จำเป็น) ทำให้ตัวนี้มีแค่ "อ่านเว็บ + เขียนลง Library"
2. **Cost และ context.** งานอ่าน paper กิน token มาก ถ้าอยู่ใน Malren จะแย่งงบ API กับงานประจำวัน และทำให้ memory ของ Malren (ที่โหลดทุกครั้ง) ปนกับข่าว AI การแยกทำให้คุมงบแยกได้ และ Malren ตอบไวเหมือนเดิม
3. **เข้ากับสถาปัตยกรรมเดิม.** Trevan และบรรณาลักษณ์เป็น specialist ประจำโดเมนอยู่แล้ว ส่วน Malren เป็น main assistant ที่รู้จักงานและชีวิตประจำวันของคุณ

ต้นทุนของการแยก:

- **RAM:** เครื่องเหลือให้ใช้ได้ราว 6.7 GiB และมี agent เพิ่มเรื่อย ๆ ต้องวัดด้วย `docker stats` ก่อนเพิ่ม container
- **งานดูแลเพิ่ม:** bot, `.env` และ backup อีกชุด
- **ความรู้กระจัดกระจาย:** แก้ด้วยการให้ทุกอย่างลง Research Library ใน Notion ที่เดียว และให้ Malren ค้นได้ (ดูหัวข้อ 5)

## 3. Research Library บน Notion

Research Library เป็น database เดียวใน Notion ที่เก็บทุกอย่างที่ VARLEN แนะนำหรือสอน และเป็นแหล่งความจริงของความรู้ ไม่ใช่ความจำของ agent

ข้อเสนอ: หนึ่งรายการ = หนึ่งแถว ใช้ canonical ID (arXiv ID, ชื่อ repo เต็ม หรือ model ID) เป็นกุญแจเช็กซ้ำ และแยกเป็น database ของตัวเอง ไม่ปนกับหน้า PARA เดิม

| ฟิลด์ | ค่าที่เก็บ | ใครเขียน |
| --- | --- | --- |
| Title | ชื่อรายการ | agent |
| Type | Repo, Open model (LLM), Open model (CV), Frontier LLM, Paper | agent |
| Canonical ID | arXiv ID, owner/repo, model ID | script |
| Source URL | ลิงก์ต้นทาง | script |
| Status | New, Recommended, Reading, Deep-dived, Skipped | agent และคุณ |
| Recommended on | วันที่แนะนำครั้งแรก | script |
| Relevance | คะแนน 1 ถึง 5 ตาม interest profile ของคุณ | agent |
| Summary | สรุปสั้นเป็นภาษาไทย | agent |
| Why it matters to me | เชื่อมกับงานหรือเรื่องที่คุณสนใจ | agent |
| Tags | หัวข้อ เช่น CV, multi-agent, robotics | agent |
| Feedback | Liked, Disliked หรือว่าง | คุณ |
| My notes | โน้ตของคุณเอง | คุณ |

ข้อกำหนด "ยังไม่เคยแนะนำ" ใช้ script เทียบ canonical ID กับ Library ก่อนส่งให้ LLM จึงแม่นและไม่เสีย token ให้ LLM จำเอง

Malren ค้น Library ได้แบบอ่านอย่างเดียว เวลาคุณถามว่าเคยเรียนเรื่อง X ไปหรือยัง

## 4. วิธีทำงาน

VARLEN ทำงานสองโหมด: Radar ที่รันตามตารางเพื่อหาของใหม่ และ Tutor ที่สอนเมื่อคุณสั่ง งานดึงข้อมูลใช้ script ธรรมดา ส่วน LLM ทำแค่คัดกรองและสรุป เพื่อคุมค่า token (ทั้งหมดในหัวข้อนี้เป็นข้อเสนอ)

**Radar: หาของใหม่ตามตาราง**

1. script ดึงรายการใหม่จากแหล่งข้อมูล เช่น arXiv, Hugging Face Daily Papers, GitHub และ RSS ของ lab หรือ blog ใหญ่ (ต้องยืนยันว่าแต่ละแหล่งเข้าถึงได้และไม่ติด rate limit ตอนเฟส 1)
2. script เทียบ canonical ID กับ Library แล้วตัดของที่เคยแนะนำออก
3. LLM ให้คะแนน Relevance ตาม interest profile ของคุณ และเลือกไม่เกินเพดานต่อวัน
4. LLM สรุปเฉพาะรายการที่เลือก เขียนลง Library (Status = Recommended) แล้วส่ง digest เข้า Discord
5. คุณกด Liked หรือ Disliked และ agent เก็บเป็น taste memory

เพดานเริ่มต้นที่เสนอคือไม่เกิน 3 รายการต่อวัน และ deep-dive 1 เรื่องต่อสัปดาห์ ปรับได้หลังดูคุณภาพจริง

**Tutor: สอนเมื่อคุณสั่ง**

เมื่อคุณสั่ง เช่น "สอน paper นี้ให้หน่อย" VARLEN ตอบตามลำดับนี้:

1. อธิบายภาพรวมแบบเข้าใจง่ายก่อน
2. นิยามศัพท์ทุกคำที่จะใช้
3. ลงรายละเอียดเทคนิค: ปัญหา วิธีการ ผลลัพธ์ และข้อจำกัด
4. เชื่อมกับงานหรือโปรเจกต์ของคุณ
5. บันทึกลง Library และเปลี่ยน Status เป็น Deep-dived

ใช้ภาษาไทยธรรมชาติปนศัพท์อังกฤษ ไม่แข็งเป็นหุ่นยนต์ และสอน paper เก่าที่ควรอ่านได้ด้วย ไม่ใช่เฉพาะของใหม่

## 5. การสื่อสารและสิทธิ์

VARLEN คุยกับคุณผ่าน Telegram bot ของตัวเอง ส่ง digest เข้า Discord และได้สิทธิ์เท่าที่งานต้องใช้เท่านั้น (ทั้งหมดในหัวข้อนี้เป็นข้อเสนอ)

&#91;embedded content: สถาปัตยกรรมของ VARLEN · 7 การเชื่อมต่อ\]

VARLEN ดึงข้อมูลจากแหล่งสาธารณะผ่าน Radar script แล้วเขียนได้เฉพาะ Library ส่วน Malren ค้น Library แบบอ่านอย่างเดียว และขอให้ VARLEN ทำงานได้ผ่านคำขอเท่านั้น

**ช่องทางสื่อสาร**

- **Telegram:** bot ของตัวเอง ไม่ใช้ร่วมกับ Malren ใช้สั่ง Tutor และถามเรื่อง paper
- **Discord:** ห้องของตัวเอง ใช้ส่ง digest อย่างเดียว
- **Notion:** Research Library เป็นที่เก็บความรู้ถาวร
- **การแจ้งเตือน 3 ระดับ:** ส่งทันทีเฉพาะเรื่องใหญ่มากที่ตรงความสนใจคุณ (เกณฑ์ตั้งตอนเฟส 2), สรุปเป็นรอบด้วย digest รายวัน, ส่วนการดึงข้อมูลปกติไม่ต้องบอก เงียบช่วง 23:00 ถึง 07:00 ยกเว้นระบบพังจริง

**สิทธิ์ที่ให้และไม่ให้**

| สิ่งที่ทำ | สิทธิ์ |
| --- | --- |
| อ่านเว็บสาธารณะ, arXiv, GitHub public | ให้ |
| เขียนและแก้แถวใน Research Library | ให้ (เฉพาะ database นี้) |
| อ่านหน้า Interest Profile หน้าเดียว | ให้ (อ่านอย่างเดียว) |
| ส่งข้อความผ่าน Telegram bot และห้อง Discord ของตัวเอง | ให้ |
| Gmail, Calendar, GitHub ส่วนตัว, หน้า Notion อื่น | ไม่ให้ |
| secrets และ `.hermes` ของ Malren และ Trevan | ไม่ให้ |
| clone, ติดตั้ง หรือรันโค้ดจาก repo ที่แนะนำ | ไม่ให้ |
| สมัครบัญชีหรือกรอกฟอร์มบนเว็บ | ไม่ให้ |

**กฎของ `agent_net`**

ข้อความจาก agent อื่นเป็น "คำขอ" ไม่ใช่ "คำสั่ง" เพื่อกันกรณี agent ตัวอื่นถูกหลอกแล้วส่งต่อคำสั่งที่เสียเงินจริง

| ระดับ | ตัวอย่าง |
| --- | --- |
| ถามได้เลย | Malren ขอค้น Library ว่าเคยเรียนเรื่อง X แล้วหรือยัง (อ่านอย่างเดียว) |
| ต้องให้คุณยืนยัน | ขอให้ไปศึกษาหัวข้อใหม่ เพราะกิน token |
| ไม่รับเลย | เขียนไฟล์, เปลี่ยนการตั้งค่า, แก้ Status ของแถวแทนคุณ |

## 6. ความจำ ความลับ และ backup

ความรู้ถาวรอยู่ใน Notion Library ส่วน memory ของ agent เก็บเฉพาะรสนิยมและสถานะการทำงาน และทุกอย่างใน `.hermes` เข้า backup กลางคืน (ทั้งหมดเป็นข้อเสนอ)

- **`.hermes` แยกของตัวเอง** เหมือน Malren และ Trevan memory จึงเป็นของตัวเองและอยู่รอดแม้สั่ง `docker compose down`
- **memory ไม่เกิน 1 ถึง 2 block:** taste memory (สิ่งที่คุณ Liked หรือ Disliked) และ interest profile ฉบับย่อ ความรู้เชิงเนื้อหาไม่เก็บใน memory
- **ledger ในเครื่อง:** ไฟล์เล็ก ๆ เก็บ canonical ID ที่เคยแนะนำ ไว้เช็กซ้ำให้เร็ว เป็นแค่แคช ถ้าหายสร้างใหม่จาก Notion ได้
- **secrets 4 อย่างใน `.env` ของตัวเอง** แยกไฟล์จาก Malren และ Trevan: Notion integration token (แชร์เฉพาะ Library และหน้า Interest Profile), Telegram bot token, Discord token หรือ webhook และ LLM API key
- **backup:** `.hermes` และ ledger เข้า restic backup กลางคืนที่มีอยู่ (Backblaze B2)
- **งบ token:** ตั้งเพดานแยกของ VARLEN ใช้โมเดลที่ถูกกว่าสำหรับ Radar และโมเดลที่เก่งกว่าเฉพาะตอน Tutor ถ้าใกล้เพดาน Radar ลดจำนวนรายการและแจ้งคุณ ไม่หยุดเงียบ ๆ

## 7. ลำดับการสร้าง

สร้างทีละเฟส เริ่มจากส่วนที่ไม่ใช้ LLM ไปหา agent เต็มรูป และแต่ละเฟสมีเกณฑ์ผ่านให้คุณตรวจก่อนไปต่อ (ทั้งหมดเป็นข้อเสนอ)

1. **เฟส 0: เตรียมโครง.** สร้าง Research Library ใน Notion, เขียนหน้า Interest Profile หนึ่งหน้า, สร้าง integration ที่แชร์เฉพาะสองอย่างนี้ และวัด RAM ด้วย `docker stats` ผ่านเมื่อ: script เพิ่มแถวทดสอบผ่าน API ได้, integration มองไม่เห็นหน้าอื่นใน workspace และ RAM พอสำหรับ container เพิ่ม
2. **เฟส 1: Radar แบบไม่มี LLM.** script ดึงรายการจากแหล่งข้อมูล เช็กซ้ำ แล้วลง Library เป็น New ผ่านเมื่อ: รันต่อเนื่องหลายวันโดยไม่มีแถวซ้ำ และทุกแหล่งที่เลือกเข้าถึงได้จริง
3. **เฟส 2: ใส่ LLM คัดกรองและสรุป.** เริ่มจำนวนน้อยตามเพดาน ส่ง digest เข้า Discord ผ่านเมื่อ: คุณอ่าน digest ช่วงหนึ่งแล้วตัดสินเองว่าคุ้มอ่าน (เกณฑ์ตัวเลขให้คุณกำหนดตอนนั้น) ถ้าไม่ผ่านให้ปรับ interest profile ก่อนไปต่อ
4. **เฟส 3: agent เต็มรูปและ Tutor.** ติดตั้ง Hermes ตัวใหม่ + Telegram bot ของตัวเอง ผ่านเมื่อ: สั่ง "สอน paper นี้" แล้วได้บทเรียนตามลำดับที่กำหนด และแถวใน Library เปลี่ยนเป็น Deep-dived
5. **เฟส 4: ความจำรสนิยมและ `agent_net`.** เปิด taste memory, ปุ่ม Liked/Disliked และให้ Malren ค้น Library ผ่านเมื่อ: หลังกด Disliked รายการแนวนั้นลดลงจริง และคำขอจาก agent อื่นที่ต้องยืนยันไม่เริ่มงานจนกว่าคุณตอบ yes

## 8. เรื่องที่ยังเปิดอยู่

ยังมี 8 เรื่องที่ต้องตัดสินก่อนหรือระหว่างสร้าง ข้อแรกกระทบการออกแบบมากที่สุด

- [ ] **รูปแบบหลัก:** เกาะติดเทรนด์ใหม่ทุกวัน หรือเรียนเป็นหลักสูตร (เช่น สัปดาห์นี้ลึกเรื่องเดียว) ข้อนี้กำหนด cadence และ schema ของ Library
- [ ] **ตัวตน:** ชื่อตั้งแล้วคือ VARLEN ส่วนน้ำเสียงและ persona ต้องตัดสินก่อนเฟส 3
- [ ] **LLM ที่ใช้:** โมเดลถูกสำหรับ Radar และโมเดลที่เก่งกว่าสำหรับ Tutor (paper ยาวต้องการ context ยาว)
- [ ] **Interest Profile:** ใครร่าง และมีหัวข้อความสนใจอะไรบ้าง
- [ ] **แหล่งข้อมูลจริง:** เลือกแหล่งที่ใช้และวิธีเข้าถึง ยืนยันตอนเฟส 1
- [ ] **ตัวเลขเริ่มต้น:** เพดานรายการต่อวัน เวลาส่ง digest และเพดาน token ต่อเดือน
- [ ] **RAM:** วัดจริงในเฟส 0 ว่า container เพิ่มอีกตัวแล้วเครื่องยังไหว
- [ ] **ความหมายของ Verification:** ให้ VARLEN ตรวจข้อกล่าวอ้างด้วยหรือไม่ เช่น เทียบ benchmark ของ repo หรือ model กับ paper ต้นทาง ถ้าใช่ จะเพิ่มขั้นตรวจใน Radar และ Tutor พร้อมฟิลด์สถานะการตรวจใน Library
